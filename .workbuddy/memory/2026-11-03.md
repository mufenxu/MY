## 登录背景视频「循环不丝滑」的真因与修复（晚间）

用户反馈循环点有明显衔接。**上一轮「479 = 240+240−1 所以天生无缝」的判断是错的**——只数了帧数，没验证首尾帧的实际内容。

**根因（两层，必须都修）**：

1. **素材首尾夹了无关帧**。逐帧解码比对：手机版 `f0`/`f478`、平板版 `f0~f2`/`f476~f478` 是「蓝绿渐变背景 + 白色卡片特写」，与主体「浅色底 + 中心橙球辐射图」完全不同（MAE 51，正常相邻帧只有 0.2~2）。播放到结尾会先切成卡片特写再跳回辐射图。用 `elst media_time=1024` 判断「跳了 2 帧」是**误判**：`seg_dur == media duration`、`ctts` 首项 offset 恰好 1024，elst 只是在抵消 B 帧的 DTS 平移，不丢帧。
2. **`REPEAT_MODE_ONE` 回环必顿**。回环要 seek 回 0，触发 codec flush + 从 IDR 重解，真机 100~250ms 定格。素材再干净也补不回来。

**修复**：

- 素材重编码。真实动画区间：手机 `f1..f477`（477 帧，闭环 MAE 0.426）、平板 `f3..f475`（473 帧，0.713）。用 PyAV 的 libx264 重编，`crf=28 preset=slow g=48 max_b_frames=2 scenecut=0 +faststart`，PSNR 51.2/50.3 dB（视觉无损），体积 2.46/2.26MB（原 2.24/2.05MB）。**本机无 ffmpeg 时可用 `pip install av numpy` 当 ffmpeg 用**，libx264/nvenc/qsv 都在。
- 播放器改双实例交替。`res/layout/view_login_backdrop.xml` 新增（`surface_type="texture_view"`，`PlayerView` 的 surface 类型**只能 XML 指定**，javap 确认没有 setTextureView/setSurfaceView）。两路 `REPEAT_MODE_OFF`：A 播到 `STATE_ENDED` 时 `B.play()` + `activeSlot=B` + `A.pause(); A.seekTo(0)`（后台回零点，被 B 遮挡时完成）。两路 TextureView 叠放，上层 alpha 0↔1 过渡 140ms；因两路内容同帧，淡化不露底色。降级：`onPlayerError`（低端机只给一个 1080p 解码器）或备用 2.5s 未出首帧 → 退回单实例 `REPEAT_MODE_ONE`。
- 海报用新素材首帧重新导出（11KB/13KB）。
- 校验：`check:android-design` 187 文件通过、`compileDebugKotlin` 通过、`lintDebug` 通过（新增文件 0 告警，`InflateParams` 用 `@SuppressLint` 抑制并注明原因）。

**待真机确认**：双实例在不同 SoC 上的解码器余量、160ms 交接过渡的实际观感。备份在 `.workbuddy/tmp/videofix/`。
