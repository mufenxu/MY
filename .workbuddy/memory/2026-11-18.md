## 图书馆座位「自动预约任务」抗学校卡顿（campus-service）

- 现象：21:55 放号时学校系统排队卡几分钟，任务落到「提交结果待确认」并 `已停用`，学校恢复后也不再去抢（截图里 `最近异常：This operation was aborted`）。
- 三个叠加的根因（务必记住，改动这块前先看）：
  1. `prepared.pending` 是**粘性**的：只有「学校明确拒绝 + 有空位可换」才清空；单纯超时（`pendingRefused=false`）即使 `lastMake` 连续确认「查不到这笔预约」也永远返回 `confirming`，等于**再也不提交**。
  2. `LIBRARY_SEAT_AUTO_TASK_RETRY_WINDOW_MS` 只有 60 秒，窗口到点 `finishLibrarySeatAutoTask` 直接把 `enabled` 置 false，任务终结。
  3. 提交/查询共用 15 秒超时，放号高峰必然 abort；abort 是没有 `status` 的 DOMException，只会在 `last_failure` 里留一句英文。
- 改法（4 个文件）：
  - `library-seat.js`：新增 `librarySeatTransportError()`，abort → `504 LIBRARY_SEAT_TIMEOUT`、连接失败 → `502 LIBRARY_SEAT_NETWORK`，中文文案；`request()`/`submitReservation()` 支持按次覆盖超时。
  - `library-seat-auto-task.js`：窗口 60s → **5 分钟**（`LIBRARY_SEAT_AUTO_WINDOW_MS` 可覆盖）；提交超时单独 30s（`LIBRARY_SEAT_AUTO_SUBMIT_TIMEOUT_MS`）；新增 `markPending()`/`clearPending()` + `pendingSince`/`pendingCleanChecks`，**连续 2 次核对无记录且距超时 ≥5 秒才清空待确认并重新提交**（防重复预约）；confirming 返回 `retryAfterMs`；整区无座改为 2s 起递增退避，运行中刷新空位只取 10 个阅览区（`REFRESH_MAX_AREAS`）。
  - `reservation-service.js`：claim 锁时长跟随窗口；**准备失败在窗口内重试**而不是直接判死；topology 布局拉取失败降级为实时空位模式；多时段路径的可重试异常不再把该时段判 failed。
  - `public/library-seat-page.js`：面板文案改成「学校繁忙会持续重试约 5 分钟」。
- 边界：`matched` 判定靠 `getMyReservations()` 的 `date`，曾要求严格相等，现改为只比前 10 位（学校可能返回 `2026-11-19 00:00:00`）。
- 验证：`services/campus-service` 251 个测试全绿（新增 5 条，含 `mock.timers` 模拟「学校卡 3 分钟再恢复仍抢到座位」）、`npm run lint` 干净、`npm run check` 通过。

## core-admin 输入框光标被裁成 8px（真 bug，已修）

- 现象：综合管理台（core-admin）所有带图标/清除按钮的输入框，聚焦后光标只有 8px 高，其他管理台正常。
- 根因：`src/styles/antd.css` 的 `.ant-input { border-radius: 10px !important }` 连 `.ant-input-affix-wrapper` 内层原生 `<input>` 一起命中，覆盖了 antd 自己的 `border-radius: 0`。内层 input 的 padding 是 0、高度只有一行（20.4px），10px 圆角≈胶囊，光标正好画在最左端圆角起弧处，Chrome 按圆角裁剪绘制区 → 18.5px 的光标被切成 8px。
- 修复：补一条 `.ant-input-affix-wrapper > .ant-input { border-radius: 0 !important; }`（圆角由外壳负责，内层只需别裁光标）。改动未涉及别的应用：exam-admin 用 Element Plus、admin-console 用 `.input-wrapper`，圆角都在外壳上。
- 排查方法备忘：Chrome headless + CDP（`Emulation.setFocusEmulationEnabled` 必须开，否则光标不绘制），把 `caret-color` 改成纯色后连拍几帧量像素，是唯一可靠的测量方式。
- 排除项：Chromium 的输入光标高度只由字体度量决定（约 1.15–1.4×字号），**不读 line-height、也不跟输入框高度走**；实测把 `line-height` 从 20.4px 改到 32px 光标纹丝不动。所以"光标短"不要先怀疑行高。
