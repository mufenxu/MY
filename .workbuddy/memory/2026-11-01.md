### 这轮踩到并修掉的坑（复查时直接照这条）

- **固定列竖带**：面板是渐变底，固定列必须不透明，antd 给的是自己的实色 → 与面板差一档，横向滚动时右列出现浅色竖带。解法：固定列 `background-color: var(--surface-solid)` + `background-image: linear-gradient(<叠层>, <叠层>)` 还原（叠层分别用 `--groove-bg` 表头 / `--hover-bg` 悬停 / `--blue-soft` 选中），并把默认浓投影换成 `inset ±1px 0 0 var(--line)`。
- **双层卡片**：Users 原来是「panel 包 Tabs，Tabs 内容又是 panel」。改为 `page-view` + `page-head` + `Tabs`，内容侧只留一层 panel（与 Settings 一致）。手机列表卡片用 `.list-card`，不要用 `.panel` + 内联 padding。
- **页签折叠成「…」**：antd 按默认 32px gutter 算宽度。≤900 收紧到 16px 才能让 7 个带文字页签排下；≤560 才退成纯图标（原来错写成 768，平板上就是一堆看不懂的图标）。
- **`.list-card-head` 是 space-between**：头像和文案要包一层 `.cell-user`，否则中间被撑开。
- **窄屏三列会被撑断行**：`.metric-grid` 在 ≤640 退两列，"45.2 °C" 才不换行。
- Chrome 截图：`--window-size=390,844` 不会被夹到 512；截图里的坐标 ≈ CSS ×2（因为 `--force-device-scale-factor=2`），裁剪时别按 CSS 值算。

## ACR 工作流 CI 误判修复（已提交 6a41694）

- 根因：`ci.yml` 是 `ci-${{ github.ref }}` + `cancel-in-progress: true`，同一分支连推两次，旧提交的 CI 必然以 `cancelled` 收尾；`aliyun-acr.yml` 只看该 SHA 最新一次运行的 conclusion，非 `success` 一律 `exit 1` → 每次快速连推都飘红。
- 改法：拆出前置 job `verify-required-ci`（输出 `proceed`），`build-and-push` 用 `needs` + `if: needs.verify-required-ci.outputs.proceed == 'true'`。
  - 同一 SHA 多次运行：只要有一次 `success` 就放行（原写法只取 `[0]`，会被重跑记录带偏）。
  - `cancelled`/`skipped` 分情况：`push` 触发 = 被更新提交顶替 → `::notice::` + 跳过，整体绿色；`workflow_dispatch` 触发 = 发布中心在等结果 → 仍报错，不许用未验证的提交出镜像。
  - 跳过时不出镜像也不回调发布中心（回调步骤在 job 内，job 不跑自然不发；发布中心只对已有 build 记录做 reconcile，不会误判成 succeeded）。
- 校验：`js-yaml` 解析通过、`bash -n` 通过；`check:supply-chain` 5/5、`check:release` 18/18、`check:conventions` 9/9、`check:topology` 2/2。
- 本机没有 `jq`，jq 表达式未做本地实跑验证（GitHub runner 自带）。

## 镜像构建缺共享包导致 CI/ACR 全线飘红（已提交 0d162a5）

- 根因：抽 `packages/pearl-tokens` 时只改了应用依赖，Dockerfile 构建阶段仍只 `COPY apps/core-admin`，`npm ci` 拿不到 `file:` 依赖，vite 报 `Rollup failed to resolve import "@my-platform/pearl-tokens"`。platform-api 镜像挂 → CI 挂 → ACR 门禁按预期拦住（门禁逻辑本身没问题，别去改它）。
- 修法：`platform-api.Dockerfile` 两个前端 stage、`core-api.Dockerfile`（拆分部署用）在 `npm ci` **之前**补 `COPY packages/pearl-tokens/`。
- 连带修：`config/image-build-targets.json` 补 `packages/pearl-tokens/**`→platform；发现 `packages/api-contract/**` 改了不重建任何镜像，补 platform/notification/campus/iot。`aliyun-acr.yml` 的 `paths` 同步补两个包。
- 新增 `scripts/release/dockerfile-local-deps.test.mjs`（已接 `check:release`，3 条断言）：
  1. 每个构建阶段必须复制应用声明过的全部 `file:` 依赖，且必须在 `npm ci` 之前；正则要能吃掉 `COPY --chown=... packages/x/` 这种带参数写法。
  2. 每个被复制进镜像的包，必须有重建规则覆盖该 Dockerfile 影响的所有目标（`core-api`/`exam-api` 没有独立目标，改动归 platform）。
  3. ACR 的 `paths` 必须监听所有被镜像内嵌的包。
  - 已用「临时删掉一行 COPY」验证能精确报出：`platform-api.Dockerfile:core-admin-build 构建 apps/core-admin 依赖 @my-platform/pearl-tokens…`。
- 验证：CI run 41272068632 全绿（Build platform-api 首次通过），ACR run 41272068649 success，镜像已 promote 到部署标签。
