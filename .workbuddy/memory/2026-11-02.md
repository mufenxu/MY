## 第二批：真 bug 修复 + 剪贴板收敛（同日续）

上面那条「下一刀：backup + diagnostics + ct8」的建议经复核**是错的**，此处更正：
`runDiagnostics` 会跨域回写 `overview/incidents/iot`，`ct8` 的消费方在 Projects 屏而不是
Operations，且 `refreshing`/`sectionError` 全部由全局 `sectionLoadStates` 派生。强行抽
holder 会得到一个要往三个域回写的对象，耦合比现状更重。**这三个域不拆。**

### 修掉的真问题：离线态残留

`runDiagnostics` / `triggerBackup` / `triggerCt8` 自行取数后直接写 `AppUiState`，绕过
`SectionRefreshController`，分区状态停在旧的 `updatedAtMillis` 与 `fromCache` 上。结果是
数据已刷新但界面还在离线态：概览页挂着离线横幅，**场景页因 `fromCache=true` 持续禁用所有控制**，
直到下一次常规刷新（且有 30s 刷新窗口挡着）。

- 分区状态写入收敛为唯一纯函数 `AppUiState.withSectionLoadState`（`ui/UiStates.kt`），
  `offlineMode` 与 `cachedAtMillis` 只由「哪些分区还在用缓存」推出。
- 新增 `SectionRefreshController.recordExternalRefresh(sections)`：只在真拿到新数据时登记。
- `runDiagnostics` 改用统一 `fetch` 包装；顺带让 `CancellationException` 正常向上抛
  （原来 `runCatching` 会把它吞成旧值，然后照常报「巡检完成」）。

### 结构改动

- `buildAssistantContext` → `ui/feature/assistant/AssistantChatContext.kt` 的纯函数
  `buildAssistantChatContext(state, campus, today, nowMillis)`；顺手修掉时间源不一致
  （接收 `nowMillis` 但未读判定自己调 `System.currentTimeMillis()`）。
- 剪贴板收敛到 `ui/components/clipboard/AppClipboard.kt`：`rememberAppClipboard()` +
  `copy/readText`，一次性凭据走 `copyEphemeralText`（敏感标记 + 到期清理 + clipId 防误删）。
  免密登录链接改为敏感复制。`AGENTS.md §10` 补登该组件。
- `StartupAnimation` 之外未再动设计系统。
