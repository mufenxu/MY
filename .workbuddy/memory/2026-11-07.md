## 校园服务账号体系核查（只读，无改动）

用户问"校园服务网站是否支持多账户登录"，走查了 `services/campus-service`：

- 系统账号是完整多用户模型：`users` 集合（`id`/`username` 唯一索引），邀请码注册或管理员创建，角色只有 `admin`/`user`；会话为 HMAC 签名 cookie（`__Host-hgu_app_session`，微信内置浏览器降级 `hgu_app_session`），带 `session_version`，改密/停用/登出即 `bumpSessionVersion`，会把该账号所有设备一起踢下线。
- 学校账号会话按用户隔离：`school_sessions` 以 `user_id` 唯一索引，读写经 `currentUserId()` + `replaceSchoolSessionIfVersion` 乐观锁；每用户只有一个 jar、只绑一个学号（`resolveSchoolAccount` 从 `jar.meta.schoolAccount` 取）。原先 MEMORY.md 记的"全局共享一份"已过时，已更正。
- 残留共享口子：平台 SSO 令牌不带 `account_id` 时退回 `PLATFORM_SSO_CAMPUS_USERNAME`（默认 admin），且该分支要求 `role=admin`（`server.js:867-888`）。
- 不支持同一浏览器多账号并行/切换：单 cookie、无账号切换 UI、无"学号已被其他账号绑定"的唯一性校验。

## 预约入口重复 + 自动任务不可用 + 座位 21:55 定时（已修复）

用户报：导航里出现两个「预约」；座位页的「自动预约任务」一直停在「正在加载自动预约任务...」；要求自动任务运行时间默认 21:55，次日座位当天 21:55 开跑。

### 根因：`?v=` 资源被 `immutable` 缓存一年

`src/lib/static-assets.js:112` —— 带 `?v=` 的响应 `public, max-age=31536000, immutable`，不带则 1 小时 / HTML `no-cache`。新增的 `reservation-hub.js`、`libroom-*.js`、`library-seat-page.js` 当初没加 `?v=`，`reservation-hub.css` 又固定写 `-v1` 后继续改内容 → 用户浏览器一直用早期副本：早期副本缺 `.resv-tabpanel[hidden]{display:none!important}`（面板串到座位页）且重复注入导航项。**以后改这些文件必须同时改版本号。**

### 修复

- `index.html`：5 个预约脚本统一 `?v=20261107-resv-v2`；同时把 `styles.css` → `20261107-overview-grid-v3`、`ui-refresh.css` → `sms-login-v2`、`app.js`/`sms-login.js` → `sms-login-v2`（这几个今天改过但没换版本号，同样会吃旧缓存）。
- `reservation-hub.js`：启动时先归一 DOM —— 多余的 `a[href="#reservation"]` 和多余的 `#reservation` 删掉；已初始化过（`.resv-switch` 在）直接 return；旧版残缺面板删掉重建。已用「注入重复项 + 动态再加载一次 hub」验证回落到 1 个导航项 / 1 个 section。
- `libroom-auto-page.js`：页面一进来就 `route()` 拉任务（`ensureSpaces` 缓存 spaces 请求），不再依赖页签事件，杜绝「永远正在加载」；`resv:refresh` 才清缓存重拉。
