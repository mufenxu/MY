## Android 分区标题副标题右对齐修复

- 现象：`今日`/`设备` 等页面的分区标题带（浅底胶囊）中，右侧说明文字（如「已接入的应用快捷访问」「常用灯光与插座」）停在标题栏中间，右侧留白。
- 根因：`ui/components/display/AppSectionHeader.kt` 中副标题用 `Modifier.weight(1f, fill = false)`。Compose 的 `fill = false` 只把子项上限设为权重份额（约 50%），按内容收缩后剩余空间不会分给兄弟节点，整行按 start 排布 → 副标题右侧出现空隙。`textAlign = TextAlign.End` 形同虚设。
- 修复：副标题改为 `Modifier.weight(1f)`（填满份额），`TextAlign.End` 才能贴到标题栏内右边缘（有 `trailing` 时贴在其左侧 8dp）。
- 覆盖面：该组件是唯一分区标题实现，53 处调用（`OverviewSectionTitle` / `ToolSectionTitle` / `ProfileSectionTitle` / `AndroidReleaseSectionTitle` / `SettingsSectionTitle` 等包装器全部委托到它），一处修复全局生效。`AndroidReleaseScreen` 的骨架占位用 `Arrangement.SpaceBetween`，本身已正确。
- 附带：`app/src/debug/.../DesignSystemPreviews.kt` 从未覆盖 `AppSectionHeader`，补了两条预览（是否带 trailing 各一），作为对齐回归的目视锚点。
- 验证：`npm run check:android-design` 通过（136 文件）；`./gradlew :app:compileDebugKotlin --offline` BUILD SUCCESSFUL（需 `JAVA_HOME=C:/Users/25912/.jdks/ms-17.0.18`，本机 PATH 无 java）；无设备（adb devices 为空），未做真机渲染验证。
- 保持 50/50 份额的原因：与修复前副标题可用宽度完全一致，只改位置，不引入新的省略风险。

## 后端与接口规范评审（产出 docs/api-contract-review.md）

- 范围：`services/` 6 个单元 + `packages/platform-auth` + `infra/nginx` + 接口文档；方法为静态阅读 + 端点盘点脚本 + 限流响应真实中间件实测。
- 盘点口径：core-api 98 个静态端点（另有 1 处 ct8 动态注册）/55 写/13 有 Joi schema（24%）；exam-api 138/74/60（81%）；notification-service 45 条路由。
- 实测确认的缺陷：core-api `globalLimiter`/`scanLimiter`/`exchangeLimiter` 超限返回 `text/html`（express-rate-limit v8 对字符串 message 走 `res.send`），导致前端 `response.json()` 抛异常。
- 其余 P0：`adminCourseOrderController.js:70`、`courseOrderController.js:516,535` 用 HTTP 200 携带业务错误码；core-api 无 `/api` 兜底 404（Express 默认 HTML）；core-api 未映射 Mongoose CastError/11000（exam-api 已做）；`download-parse.mjs` SSRF 黑名单可被 DNS/十进制 IP/端口绕过；iot `system.js:82` 500 泄露 error.message。
- 结构性结论：5 种成功信封 + core-api 内 3 种 429（含 text/html）、4 种分页响应、10 个健康/版本路径、仅 notification 有 OpenAPI、0 契约测试；`docs/core-api-usage.md` 实为企微通知教程且被 AGENTS.md 误指向 SSO。
- 建议路线：Phase1 修行为（不改协议）→ Phase2 统一错误契约（本地 respond.js，先不进 packages）→ Phase3 健康/观测/网关路由表 → Phase4 OpenAPI + `/v1` + 幂等/If-Match。
- 明确守住的红线：不一次性重写 5 种信封、不对齐 limit/pageSize 优先级、不换日志库、不引入 jest/Prettier。

## 接口层升级落地（同日，第二轮）

- 新增契约包 `packages/api-contract/`（`error-codes.json` 54 个码 + `index.cjs` 门面）。**没有放 `config/`**：只有 `packages/` 被 4 个 Dockerfile 整体复制，放 `config/` 要改 6 处 COPY 且路径不一致。
- 统一失败信封（仅 4xx/5xx）：`{ok:false,success:false,code,error,message,details?,requestId}`。`error` 与 `message` 都保留且都是**字符串**，因为 core-admin 读 `error`、exam-admin 读 `message`、多处判 `res.data.success`；成功体一律不动（exam 的 `code:0` 被 3 处前端判断）。
- 落地位置：core-api `utils/respond.js` + `middleware/{errorHandler,rateLimit,validate}.js` + `/api` 兜底 404；exam-api `src/utils/respond.js` + errorHandler + response.error；iot 500 改走 `next(error)`；下载解析失败沿用既有 code。
- 限流：四个 + 两个公开限流器共用一个 `createRateLimitedHandler`，429 回 JSON 且带 `Retry-After`；已实测 content-type 为 application/json。
- SSRF：`assertFetchableTarget()` = 协议 + 无凭证 + 仅 80/443 + 平台白名单（douyin/iesdouyin/haijiao）跳过 DNS + 其余 `dns.lookup(all:true)` 任一结果落在内网即拒；`isPrivateAddress` 覆盖 IPv4 私有/CGNAT/链路本地/组播、IPv6 ULA/LL、IPv4-mapped、NAT64；短链改 `redirect:'manual'` 逐跳校验（≤5 跳）。
- 健康：6 个单元统一 `/livez` `/readyz` `/version`，旧路径保别名；网关自带 `/readyz`（此前由门户代答，`service` 字段是 admin-console）；镜像 HEALTHCHECK 切到 `/readyz`；门户 config 的 healthPath 刻意留在旧路径（无回落逻辑）。
- 网关：`SERVICE_ROUTE_TABLE` + `matchServiceRoute`（最长前缀），替代 9 段 if/else；AI 长耗时改为条目级 `longRunning`；`rewriteServicePrefix` 保留清单补 `/livez` `/readyz`（否则会被改写成 `/api/readyz`）。
- 校验：core `middleware/validate.js` 同时支持 `validate(joiSchema)`（存量 13 处，只校验 body）与 `validate({body,query,params})`；`stripUnknown:true`；Express 5 的 `req.query` 是只读 getter，必须原地替换。
- 分页：新增 `buildPageMeta`，用户/审计列表增量挂 `page`；请求侧 `limit`/`pageSize` 优先级仍不对齐。
- 检查：新增 `scripts/checks/check-error-codes.mjs` + 测试，接 `npm run check:contract` 并进 `check` 链；棘轮只扫"引用了 respond 的文件"，避免一次性判红存量。
- 新增测试：core `test/error-contract.test.js`（404/429/CastError/500 脱敏/成功体不变）、platform-api 路由表与探针路径、`isPrivateAddress`/`assertFetchableTarget` 8 组用例、`buildPageMeta`。
- 文档：新增 `docs/api-specification.md`；`docs/core-api-usage.md` → `docs/notification-api-usage.md`，AGENTS.md 导航改指正确文件；`engineering-standards.md §7` 改述"失败响应已统一、成功体不动"。
- 刻意没做：抽通用 Idempotency/If-Match 中间件（todo 的 `todo-N` ETag + revision 冲突快照是领域耦合的，抽出来比原代码更长，违反"不为统一而统一"）；全量 OpenAPI 生成；`/v1` 前缀。
