## 内置浏览器登录态丢失修复（WebView 与平台会话解耦）

现象：内置浏览器里的第三方站点（含统一认证）登录态隔天就没了，每次要重输密码。

根因：`SessionStore.hasSession()` 判定平台会话过期时会 `clear()`，而 `clear()` 无条件调 `WebSessionStore.clear()`（`removeAllCookies` + `WebStorage.deleteAllData`）；`writeLogin()` 每次登录成功也清一遍。平台 idle 超时默认 30 分钟，隔夜首次启动必然触发，于是浏览器数据被连带清空。

改动（3 处代码 + 1 条规范）：
1. `SessionStore.clear(deleteDeviceKey = true, clearWebSessions = false)` 新增开关，默认**不**清 WebView。
2. `writeLogin()` 只在 `last_username != 当前账号`（换账号）时才清 WebView；同账号重登保留。
3. `PlatformAuthRepository.logout()` 显式传 `clearWebSessions = true`（主动登出=交出设备），并在会话锁**外** `WebSessionStore.awaitCleared()` 等落盘（锁内挂起会阻塞其它线程）。
4. `PlatformWebActivity.onPause()` 补 `CookieManager.flush()`，避免进程被系统回收时未落盘 Cookie 丢失。
5. `apps/android-app/AGENTS.md` §9 增加红线：平台会话与内置浏览器登录态必须解耦。

验证：`check:android-design` 通过；`:app:compileDebugKotlin` 通过。

未解决边界：主动退出登录仍会清空网站登录态（安全语义：交出设备）。若用户希望登出后也保留，需产品决策后再改 `logout()` 的传参。

## admin-console 外部应用「保存没反应」修复

现象：控制台编辑外部应用（蜜雪后台，kind=direct，访问地址 http://mxwk.online）点保存无反馈；网络面板 `PUT /api/external-apps/:id` 返回 400。

根因两层：
1. `external-application-service.js` 的 `secureHttpUrl` 只对 `autoLogin` 放行 HTTP（`allowInsecure: Boolean(autoLogin)`），**direct 类型没放行** → 生产环境抛「启动地址必须使用 HTTPS」→ 400。
2. 前端把错误塞进页面级 `error` 状态，横幅渲染在弹窗背后的列表顶部，被遮罩挡住 → 看起来毫无反应（弹窗也不关）。

改动：
- direct 类型放行明文 HTTP（启动地址 + 健康检查地址），OIDC / 自动登录仍强制 HTTPS。安卓 `network_security_config.xml` 早已给 mxwk.online 开明文豁免，方向一致。
- `ExternalApplicationsView.jsx`：`ApplicationEditor` 新增 `error` 入参，保存失败横幅显示在弹窗内；新增 `openEditor()` 打开时清空错误；页面级横幅改为弹窗关闭时才显示；HTTP 地址给 `.external-app-note` 黄色提示（样式加在 `styles/pearl/views.css`）。
- 测试：service 层 direct+http 放行、OIDC 仍拒；接口层 PUT 明文地址返回 200；前端源码断言弹窗内渲染 error-banner。全量 `npm test` 193 例通过，lint 0 error，`vite build` 通过。

## 生产库被删 → 恢复事故复盘（pxyb.cn）

现象链：宝塔删 Compose 项目后数据卷被重建为空库 → 管理员登录不了（passkey 全无）→ 用恢复链接 + 平台内备份点恢复 → 恢复后所有服务报 `MongoServerError: Command xxx requires authentication`（code 13，连上但未认证）。

根因（三条叠加）：
1. `scripts/database/backup-mongodb-container.mjs` 的 `mongodump` **没带 `--dumpDbUsersAndRoles`**，`restore-mongodb-container.mjs` 却带 `--drop --oplogReplay` → 恢复后各业务库 `system.users` 与数据不一致。
2. `mongodb-init`（`infra/docker/ensure-users.js`）是账号的唯一真相源，但恢复流程不会自动重跑它。
3. 服务器 `.env` 被 Windows 编辑器写成 **CRLF** → `docker compose` 全部命令报 `parsing "0\r": invalid syntax`（`cpus: ${X:-0}` 被解析成 `0\r`），`up/restart/ps` 全部静默失效，误导判断。

修复口径（已验证可登）：
```bash
cd /www/server/panel/data/compose/my-platform
cp -a .env .env.bak.$(date +%Y%m%d-%H%M%S)
sed -i 's/\r$//' .env
docker compose config -q                      # 必须看到 CONFIG_OK 再做下一步
docker compose up -d --force-recreate mongodb-init
docker compose run --rm -T --no-deps mongodb-init   # 幂等：按 .env 重设全部 app 账号口令
docker compose up -d --force-recreate notification-service
docker compose up -d --force-recreate campus-service iot-service
docker compose up -d --force-recreate platform-api
docker compose up -d --force-recreate core-api exam-api backup-runner
```
**红线：`docker compose restart` 不会重读 `.env`**，改完 `.env` 必须 `up -d --force-recreate`，否则容器沿用旧环境变量，与库里新口令对不上。

其他确认：`admin` 库 root 未被覆盖；`my-platform_platform_backups` 卷自 2026-11-01 创建以来**为空**，自动备份链路从未跑通过（待修，是本次无可用备份的直接原因）；恢复按钮「点不动」是 `BackupRecoveryView.jsx` 中 `RESTORE ALL DATA` 为占位符需手输。
