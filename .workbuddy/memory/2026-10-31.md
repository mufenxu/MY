### 三、这轮踩到的坑（重要，下次别再踩）

1. **无头 Chrome 有 ~512px 最小窗口宽度**。`--window-size=390,1500` 实测 `innerWidth=512`，截图却输出 390 宽（缩放），于是所有"右边被裁"现象都是**测试假象**。正确做法：写一个 iframe 页，iframe 固定 390 宽并定位在 (0,0)，窗口开 800 宽，截图后按 `(0,0,w,h)` 精确裁剪。校准页 `viewport.html` 打印 innerWidth 可验证。
2. **`--hide-scrollbars` 不改变布局**，别拿它当理由。
3. **旧 CSS 的加载顺序会反杀**：`auth.css` 里的 `.backup-layout` 1280 断点单列规则，被后加载的 `backup.css` 基础三列规则盖掉。同理 `features/notifications.css` 620 断点用 `.notify-toolbar .ops-segmented button { flex:1 }`（特异性 0,2,1）把 8 个标签等分压缩、长标签溢出。**在 responsive.css 里必须用同等或更高特异性的选择器覆盖**，单类选择器打不过。
4. 我在 `ops.css` 加的 `@media (max-width:1180px) { .backup-kpis { 2 列 } }` 会覆盖旧文件 760 断点的单列规则 —— 已改成 `@media (min-width:761px) and (max-width:1180px)`，只负责平板区间。
5. **长路径文本会把整个外壳网格撑宽**：备份页 `C:/Users/.../my/backups` 让 `.app-frame` 的 grid 列跑到 1018px（视口 390），表现为"所有卡片右边被裁、但 body.scrollWidth 还是 390"（因为 `.content` 有 `overflow-x:clip`）。修法是给 `.app-frame/.workspace/.content/.page/.page-body/.page-view` 全部补 `min-width:0; max-width:100%`。
6. `.data-row > .tag` 作为 grid item 会被 `justify-self:stretch` 拉满整列，要单独设 `justify-self:start`。
7. 移动端抽屉 `.rail` 的 `--rail-bg` 是 0.92 透明度，浮在内容上会透出下层卡片，≤900 改 `background:var(--surface-solid)`。
